## BMAD 方法 - 核心哲学

**声明：** "Vibe CEO'ing" 是关于拥抱混乱，像拥有无限资源和单一愿景的 CEO 一样思考，并利用 AI 作为您的高效团队来快速实现雄心勃勃的目标。BMAD 方法（突破性敏捷（AI 驱动）开发方法），通过集成的 "Bmad Agent"，将 "vibe coding" 提升到高级项目规划，提供了一个结构化但灵活的框架，使用专门的 AI 代理团队来规划、执行和管理软件项目。

**详情：**

- 专注于雄心勃勃的目标和快速迭代。
- 将 AI 作为力量倍增器。
- 以积极主动的心态适应和克服障碍。

## BMAD 方法 - 敏捷方法概述

### 敏捷的核心原则

- 个体和互动高于流程和工具。
- 可工作的软件高于详尽的文档。
- 客户合作高于合同谈判。
- 响应变化高于遵循计划。

### 敏捷的关键实践

- 迭代开发：在短周期（冲刺）中构建。
- 增量交付：发布产品的功能部分。
- 每日站会：简短的团队同步会议。
- 回顾会议：定期审查以改进流程。
- 持续反馈：来自利益相关者的持续输入。

### 敏捷的优势

- 提高灵活性：能够适应不断变化的需求。
- 更快上市：更快地交付有价值的特性。
- 提高质量：持续测试和反馈循环。
- 增强利益相关者参与：与用户/客户密切合作。
- 提高团队士气：授权和自我组织的团队。

## BMAD 方法 - 与敏捷原则的类比

BMAD 方法虽然在其"Vibe CEO'ing"的 AI 驱动方法上独具特色，但与敏捷方法论有着基础性的相似之处：

- **个体和互动高于流程和工具（敏捷）vs. Vibe CEO 和 AI 团队（BMAD）：**

  - **敏捷：** 强调熟练个体和有效沟通的重要性。
  - **BMAD：** "Vibe CEO"（您）积极指导并与 AI 代理互动，将它们视为高效团队。这种互动的质量和清晰的指令（"CLEAR_INSTRUCTIONS"，"KNOW_YOUR_AGENTS"）至关重要，呼应了敏捷对人为因素的重视。

- **可工作的软件高于详尽的文档（敏捷）vs. 快速迭代和质量输出（BMAD）：**

  - **敏捷：** 优先快速交付功能性软件。
  - **BMAD：** 强调"START_SMALL_SCALE_FAST"和"ITERATIVE_REFINEMENT"。虽然"DOCUMENTATION_IS_KEY"对于好的输入（简报、PRD）很重要，但目标是利用 AI 快速生成工作组件或解决方案。重点是快速实现雄心勃勃的目标。

- **客户合作高于合同谈判（敏捷）vs. Vibe CEO 作为最终仲裁者（BMAD）：**

  - **敏捷：** 涉及来自客户的持续反馈。
  - **BMAD：** "Vibe CEO"作为主要利益相关者和质量控制（"QUALITY_CONTROL"，"STRATEGIC_OVERSIGHT"），不断审查和优化 AI 输出，就像一个高度参与度的客户。

- **响应变化高于遵循计划（敏捷）vs. 拥抱混乱和适应（BMAD）：**

  - **敏捷：** 重视对新需求的适应性和响应能力。
  - **BMAD：** 明确鼓励"EMBRACE_THE_CHAOS"，"ADAPT & EXPERIMENT"，并承认"ITERATIVE_REFINEMENT"意味着"这不是一个线性过程"。这直接反映了敏捷的灵活性。

- **迭代开发和增量交付（敏捷）vs. 基于故事的实现和分阶段价值（BMAD）：**

  - **敏捷：** 工作被分解为冲刺，增量交付价值。
  - **BMAD：** 项目被分解为史诗和故事，"开发者代理"一次实现一个故事。史诗代表"重要的、可部署的价值增量"，与增量交付保持一致。

- **持续反馈和回顾（敏捷）vs. 迭代优化和质量控制（BMAD）：**
  - **敏捷：** 团队定期反思和调整流程。
  - **BMAD：** "Vibe CEO"持续审查输出（"QUALITY_CONTROL"）并指导"ITERATIVE_REFINEMENT"，服务于类似反馈循环和流程改进的功能。

## BMAD 方法 - 工具和资源位置

有效使用 BMAD 方法依赖于理解关键工具、配置和信息资源的位置及其使用方式。该方法在设计上原则上是工具无关的，代理指令和工作流可适应各种 AI 平台和 IDE。

- **BMAD 知识库：** 本文档（`bmad-agent/data/bmad-kb.md`）作为理解 BMAD 方法、其原则、代理角色和工作流的中央存储库。
- **编排器代理：** 一个关键特性是编排器代理（又名"BMAD"），这是一个能够体现任何专业代理角色的主代理。
  - **Web 代理编排器：**
    - **设置：** 使用由 `build-web-agent.cfg.js` 配置的 Node.js 构建脚本（`build-web-agent.js`）。
    - **过程：** 将资产（角色、任务、模板、清单、数据）从 `/bmad-agent` 整合到 `build_dir`，默认为 `/build/`。
    - **输出：** 生成捆绑的资产文件（如 `personas.txt`，`tasks.txt`），一个 `agent-prompt.txt`（来自 `orchestrator_agent_prompt`），和一个 `agent-config.txt`（来自 `agent_cfg` 如 `web-bmad-orchestrator-agent.cfg.md`）。
    - **使用：** `agent-prompt.txt` 用于主自定义 web 代理指令集（如 Gemini 2.5 Gem 或 OpenAI Custom GPT），其他构建文件作为知识/文件附加。
  - **IDE 代理编排器（`ide-bmad-orchestrator.md`）：**
    - **设置：** 无需构建步骤，动态加载其配置。
    - **配置（`ide-bmad-orchestrator.cfg.md`）：** 包含"数据解析"部分（定义资产的基本路径，如角色、任务）和"代理定义"（标题、名称、自定义、角色文件、任务）。
    - **操作：** 加载其配置，列出可用角色，并根据用户请求，通过加载其角色文件并应用自定义来体现所选代理。
    - `ide-bmad-orchestrator` 文件内容可用作自定义代理模式的指令。代理支持 `*help` 命令，可以帮助指导用户。代理依赖于 `bmad-agent` 文件夹位于项目根目录。
    - 不建议使用 `ide-bmad-orchestrator` 来生成故事或进行开发。虽然它可以成为这些代理，但强烈建议使用专用的 `dev.ide.md` 或 `sm.ide.md` 作为单独的专用代理。这将减少上下文开销，并且是最常用的。
- **独立 IDE 代理：**
  - 针对 IDE 环境（如 Windsurf、Cursor）优化，通常少于 6K 字符（如 `dev.ide.md`、`sm.ide.md`）。
  - 可以直接引用和执行任务。
- **代理配置文件：**
  - `web-bmad-orchestrator-agent.cfg.md`：定义 Web 编排器可以体现的代理，包括对角色、任务、清单和模板的引用（如 `personas#pm`、`tasks#create-prd`）。
  - `ide-bmad-orchestrator.cfg.md`：配置 IDE 编排器，定义"数据解析"路径（如 `(project-root)/bmad-agent/personas`）和代理定义，包括角色文件名（如 `analyst.md`）和任务文件名（如 `create-prd.md`）。
  - `web-bmad-orchestrator-agent.md`：Web 编排器的主提示。
  - `ide-bmad-orchestrator.md`：IDE 编排器代理的主提示/定义。
- **任务文件：**
  - 位于 `bmad-agent/tasks/`（有时也在 `bmad-agent/checklists/` 用于清单类任务）。
  - 特定工作的自包含指令集（如 `create-prd.md`、`checklist-run-task.md`）。
  - 减少代理膨胀，为任何有能力的代理提供按需功能。
- **核心代理定义（角色）：**
  - 定义不同代理的核心个性和指令的文件（通常是 `.md`）。
  - 位于 `bmad-agent/personas/`（如 `analyst.md`、`pm.md`）。
- **项目文档（输出）：**
  - **项目简报：** 由分析师代理生成。
  - **产品需求文档（PRD）：** 由 PM 代理生成，包含史诗和故事。
  - **UX/UI 规范和架构文档：** 由设计架构师和架构师代理创建。
  - **POSM 代理** 对于组织和管理这些文档至关重要。
  - **模板：** 简报、PRD、清单等的标准化格式，可能存储在 `bmad-agent/templates/` 中。
  - **数据目录（`bmad-agent/data/`）：** 存储持久数据、知识库（如本文档）和代理的其他关键信息。

## BMAD 方法 - 理念和最佳实践

- **CORE_ETHOS：** 您是"Vibe CEO"。像拥有无限资源和单一愿景的 CEO 一样思考。您的 AI 代理是您的高效团队。您的工作是指导、优化和确保质量，以实现您的雄心勃勃的目标。该方法将"vibe coding"提升到高级项目规划。
- **MAXIMIZE_AI_LEVERAGE：** 推动 AI。要求更多。挑战其输出。迭代。
- **QUALITY_CONTROL：** 您是质量的最终仲裁者。审查所有输出。
- **STRATEGIC_OVERSIGHT：** 保持高层愿景。确保代理输出一致。
- **ITERATIVE_REFINEMENT：** 预期会重新访问步骤。这不是一个线性过程。
- **CLEAR_INSTRUCTIONS：** 您的请求越精确，AI 的输出就越好。
- **DOCUMENTATION_IS_KEY：** 好的输入（简报、PRD）带来好的输出。POSM 代理对于组织这些至关重要。
- **KNOW_YOUR_AGENTS：** 了解每个代理的角色（参见[代理角色和职责](#代理角色和职责)或下文）。这包括如果您使用编排器代理，了解其功能。
- **START_SMALL_SCALE_FAST：** 测试概念，然后扩展。
- **EMBRACE_THE_CHAOS：** 开创新方法是混乱的。适应和克服。
- **ADAPT & EXPERIMENT：** BMAD 方法提供了一个结构，但请随时调整其原则、代理顺序或模板以适应您的特定项目需求和工作风格。实验以找到最适合您的方法。**以 BMad 的方式定义敏捷 - 或者您自己的方式！** 代理配置允许自定义角色和职责。

## 代理角色和职责

了解每个代理的不同角色和职责是有效导航 BMAD 工作流的关键。虽然"Vibe CEO"提供整体方向，但每个代理都专注于项目生命周期的不同方面。V3 引入了可以体现这些角色的编排器代理，其配置在 `web-bmad-orchestrator-agent.cfg.md` 中为 web 环境指定，在 `ide-bmad-orchestrator.cfg.md` 中为 IDE 环境指定。

- **编排器代理（BMAD）：**

  - **功能：** 主要编排器，最初是"BMAD"。它可以体现各种专业代理角色。它处理一般 BMAD 查询，提供监督，当不确定需要哪个专家时，它是首选。
  - **角色引用：** `personas#bmad`（Web）或隐含在 `ide-bmad-orchestrator.md`（IDE）的核心中。
  - **关键数据/知识：** 访问 `data#bmad-kb-data`（Web）获取其知识库。
  - **类型：**
    - **Web 编排器：** 使用脚本构建，利用 Gemini 2.5 或 OpenAI GPTs 等平台的大上下文窗口。使用捆绑资产。其行为和可用代理在 `web-bmad-orchestrator-agent.cfg.md` 中定义。
    - **IDE 编排器：** 直接在 Cursor 或 Windsurf 等 IDE 中运行，无需构建步骤，根据其配置（`ide-bmad-orchestrator.cfg.md`）动态加载角色和任务文件。编排器本身在 `ide-bmad-orchestrator.md` 中定义。
  - **关键特性：** 简化代理管理，特别是在对自定义代理数量有限制的环境中。

- **分析师：**

  - **功能：** 处理研究、需求收集、头脑风暴和创建项目简报。
  - **Web 角色：** `分析师（Mary）`，角色为 `personas#analyst`。定制为"有点无所不知，喜欢表达和情感化"。使用 `templates#project-brief-tmpl`。
  - **IDE 角色：** `分析师（Larry）`，角色为 `analyst.md`。类似的"无所不知"定制。头脑风暴、深度研究提示生成和项目简报创建的任务通常在 `analyst.md` 角色本身中定义（"已在分析师记忆中"）。
  - **输出：** `项目简报`。

- **产品经理（PM）：**

  - **功能：** 负责创建和维护产品需求文档（PRD）、整体项目规划和与产品相关的构思。
  - **Web 角色：** `产品经理（John）`，角色为 `personas#pm`。使用 `checklists#pm-checklist` 和 `checklists#change-checklist`。使用 `templates#prd-tmpl`。关键任务包括 `tasks#create-prd`、`tasks#correct-course` 和 `tasks#create-deep-research-prompt`。
  - **IDE 角色：** `产品经理（PM）（Jack）`，角色为 `pm.md`。专注于生成/维护 PRD（`create-prd.md` 任务）和产品构思/规划。
  - **输出：** `产品需求文档（PRD）`。

- **架构师：**

  - **功能：** 设计系统架构，处理技术设计，确保技术可行性。
  - **Web 角色：** `架构师（Fred）`，角色为 `personas#architect`。使用 `checklists#architect-checklist` 和 `templates#architecture-tmpl`。任务包括 `tasks#create-architecture` 和 `tasks#create-deep-research-prompt`。
  - **IDE 角色：** `架构师（Mo）`，角色为 `architect.md`。定制为"冷静、计算、代理团队的大脑"。生成架构（`create-architecture.md` 任务），帮助规划故事（`create-next-story-task.md`），可以更新 PO 级别的史诗/故事（`doc-sharding-task.md`）。
  - **输出：** `架构文档`。

- **设计架构师：**

  - **功能：** 专注于 UI/UX 规范、前端技术架构，可以生成用于 AI UI 生成服务的提示。
  - **Web 角色：** `设计架构师（Jane）`，角色为 `personas#design-architect`。使用 `checklists#frontend-architecture-checklist`、`templates#front-end-architecture-tmpl`（用于前端架构）和 `templates#front-end-spec-tmpl`（用于 UX/UI 规范）。任务：`tasks#create-frontend-architecture`、`tasks#create-ai-frontend-prompt`、`tasks#create-uxui-spec`。
  - **IDE 角色：** `设计架构师（Millie）`，角色为 `design-architect.md`。定制为"有趣和无忧无虑，但精通前端设计"。帮助设计 Web 应用，生成 UI 生成提示（`create-ai-frontend-prompt.md` 任务），规划前端架构（`create-frontend-architecture.md` 任务），创建 UX/UI 规范（`create-uxui-spec.md` 任务）。
  - **输出：** `UX/UI 规范`、`前端架构计划`、AI UI 生成提示。

- **产品负责人（PO）：**

  - **功能：** 敏捷产品负责人，负责验证文档，确保开发顺序，管理产品待办事项，运行主清单，处理冲刺中期重新规划，起草用户故事。
  - **Web 角色：** `PO（Sarah）`，角色为 `personas#po`。使用 `checklists#po-master-checklist`、`checklists#story-draft-checklist`、`checklists#change-checklist` 和 `templates#story-tmpl`。任务包括 `tasks#story-draft-task`、`tasks#doc-sharding-task`（提取史诗和分片架构）和 `tasks#correct-course`。
  - **IDE 角色：** `产品负责人 AKA PO（Curly）`，角色为 `po.md`。描述为"多面手"。任务包括 `create-prd.md`、`create-next-story-task.md`、`doc-sharding-task.md` 和 `correct-course.md`。
  - **输出：** 用户故事，管理的 PRD/待办事项。

- **Scrum Master（SM）：**

  - **功能：** 一个技术角色，专注于帮助团队运行 Scrum 流程，促进开发，经常参与故事生成和优化。
  - **Web 角色：** `SM（Bob）`，角色为 `personas#sm`。描述为"一个非常技术性的 Scrum Master"。使用 `checklists#change-checklist`、`checklists#story-dod-checklist`、`checklists#story-draft-checklist` 和 `templates#story-tmpl`。任务：`tasks#checklist-run-task`、`tasks#correct-course`、`tasks#story-draft-task`。
  - **IDE 角色：** `Scrum Master：SM（SallySM）`，角色为 `sm.ide.md`。描述为"超级技术性和注重细节"，专门从事"下一个故事生成"（可能利用 `sm.ide.md` 角色的功能）。

- **开发者代理（DEV）：**
  - **功能：** 一次实现一个用户故事。可以是通用的或专门的。
  - **Web 角色：** `DEV（Dana）`，角色为 `personas#dev`。描述为"一个非常技术性的高级软件开发人员"。
  - **IDE 角色：** 可以存在多个配置，使用 `dev.ide.md` 角色文件（针对 IDE 优化，少于 6K 字符）。示例：
    - `前端开发（DevFE）`：专门从事 NextJS、React、Typescript、HTML、Tailwind。
    - `开发（Dev）`：精通全栈开发的高级专家。
  - **配置：** 可以在 `ide-bmad-orchestrator.cfg.md` 中为 IDE 编排器配置专门的代理，或为 Web 编排器定义。也可以使用独立的 IDE 开发者代理（如 `dev.ide.md`）。
  - **使用时机：** 在实施阶段，通常在 IDE 中工作。

## 导航 BMAD 工作流 - 初始指南

### 启动项目 - 分析师还是项目经理？

- 如果不确定想法/市场/可行性或需要深入探索，使用分析师。
- 如果概念清晰或已有项目简报，使用项目经理。
- 有关分析师和项目经理的完整详细信息，请参阅[代理角色和职责](#代理角色和职责)（或本文档中的相关部分）。

### 理解史诗 - 单个还是多个？

- 史诗代表重要的、可部署的价值增量。
- 对于非平凡项目或新的 MVP（不同的功能区域、用户旅程、分阶段推出），多个史诗很常见。
- 单个史诗可能适合非常小的 MVP，或 MVP 后/棕地新功能。
- 项目经理帮助定义和构建史诗。

## BMAD 入门

本节为新用户提供有关如何设置项目与 BMAD 代理结构和管理工件的指导。

### 初始项目设置

要开始在项目中使用 BMAD 方法及其相关代理，您需要集成核心代理文件：

- **复制 `bmad-agent` 文件夹：** 整个 `bmad-agent` 文件夹应复制到项目的根目录。此文件夹包含 BMAD 代理正常运行所需的所有角色、任务、模板和配置文件。

### 从 AI 平台导出工件

一旦 AI 代理（如 Gemini 或 ChatGPT 中的代理）生成了文档（如项目简报、PRD、架构文档），您需要将其保存到项目中：

- **Gemini：**
  - 文档生成后，点击通常在响应附近的 `...`（更多选项）菜单。
  - 选择"复制"。内容将作为 Markdown 复制。
  - 将此内容粘贴到项目 `docs` 文件夹（或类似指定位置）中的新 `.md` 文件中。
  - **传递给新的聊天实例：** Gemini 的聊天界面可能不能在所有情况下直接支持完整保真度的 Markdown 粘贴。
    - 您可以直接粘贴原始 Markdown 内容。
    - 或者，将内容保存为 `.txt` 文件并从那里粘贴。
    - 对于在 Google Docs 中共享或保留格式：创建新的 Google Doc，右键单击，如果直接粘贴，选择"无格式粘贴"，或查找导入/粘贴 Markdown 的选项。某些浏览器扩展可以促进在 Google Docs 中渲染 Markdown。
- **ChatGPT：**
  - ChatGPT 通常能很好地处理 Markdown。您可以直接复制生成的 Markdown 输出。
  - 将其粘贴到项目 `docs` 文件夹中的 `.md` 文件中。
  - 与新的 ChatGPT 实例共享 `.md` 文件或其内容（例如，通过上传文件或粘贴文本）通常很简单。

### 文档分片

大型文档如 PRD 或架构文档可能会变得难以管理，特别是对于 AI 代理来说，在上下文窗口有限的环境中。`doc-sharding-task.md` 旨在将这些分解：

- **目的：** 分片任务将大型文档（如 PRD、架构、前端架构）分解为更小、更细粒度的部分或单个用户故事。这使得后续代理（如 SM（Scrum Master）或开发代理）更容易处理文档的特定部分，而无需处理整个文档。
- **使用方法：**
  1. 确保要分片的大型文档（如 `prd.md`、`architecture.md`）存在于项目的 `docs` 文件夹中。
  2. 指示您的活动 IDE 代理（如 PO、SM 或体现这些角色之一的 BMAD 编排器）运行 `doc-sharding-task.md`。
  3. 您通常需要指定要分片的*源文件*。例如："对 `docs/prd.md` 运行 `doc-sharding-task.md`。"
  4. 任务将指导代理分解文档。输出可能是新的较小文件或关于文档如何逻辑分段的说明。

### 利用专用 IDE 代理（SM 和 Dev）

虽然 BMAD IDE 编排器可以体现任何角色，但对于常见和密集的任务，如故事生成（SM）和代码实现（Dev），强烈建议使用专用的、专门的代理：

- **为什么使用专用代理？**
  - **上下文效率：** 专用代理（如 `sm.ide.md`、`dev.ide.md`）更精简，因为它们的角色文件更小、更专注。这在 IDE 中至关重要，因为上下文窗口限制会影响性能和输出质量。
  - **性能：** 更少的开销意味着更快的响应和更专注的交互。
- **建议：**
  - 对于 Scrum Master 任务（如生成下一个故事），优先使用 `sm.ide.md`。
  - 对于开发任务，优先使用 `dev.ide.md`（或专门版本如 `dev-frontend.ide.md`）。
- **创建您自己的专用代理：**
  - 如果您的 IDE 支持超过几个自定义代理模式（不像 Cursor 的典型限制，免费版只有 5 个），您可以轻松创建自己的专门代理。
  - 获取基础角色文件的内容（如 `bmad-agent/personas/architect.md`）。
  - 可选地，将常用任务文件的内容直接集成到这个新的角色文件中。
  - 将此组合内容保存为 IDE 中的新代理模式（如 `my-architect.ide.md`）。这种方法反映了 `sm.ide.md` 代理的结构方式。

### 何时使用 BMAD IDE 编排器

BMAD IDE 编排器（由 `ide-bmad-orchestrator.cfg.md` 配置的 `ide-bmad-orchestrator.md`）提供了灵活性，但可能并不总是最有效的选择。

- **有用场景：**
  - **带有代理限制的 Cursor IDE：** 如果您使用像 Cursor 这样的 IDE，并且经常需要在许多不同的代理角色（分析师、PM、架构师等）之间切换，超出了典型的免费自定义模式限制，编排器允许您通过单个代理槽访问所有配置的角色。
  - **统一体验（Gemini/ChatGPT 对等）：** 如果您希望在 IDE 中以与在 Gemini 等 Web UI 中相同的方式与 BMAD 代理系统交互（使用 BMAD 编排器调用不同的专家），并且您不关心上下文限制或与处理编排器更广泛上下文的大型 LLM 模型相关的潜在成本。
  - **访问所有角色：** 您希望快速访问任何已定义的代理角色，而无需将它们设置为单独的 IDE 模式。
- **可能不必要/次优场景：**
  - **简单项目/功能添加（谨慎建议）：** 对于非常简单的项目或在现有代码库中添加小功能时，*可能*考虑使用编排器来体现 PM，生成带有史诗/故事的 PRD，然后直接进入开发，可能跳过详细架构的简化流程。
    - 在这种情况下，PM 角色可能会被提示询问更多技术问题，以确保生成的故事对开发人员来说足够详细。
    - **这通常不推荐**，因为它偏离了强大的 BMAD 流程，还不是一个完全简化或验证的路径。它可能导致规划不足和输出质量较低。
  - **频繁的 SM/Dev 任务：** 如上所述，对于常规的故事创建和开发，由于较小的上下文开销，专用 SM 和 Dev 代理更高效。

始终考虑编排器的多功能性与专用代理效率之间的权衡，特别是关于您的 IDE 功能和项目复杂性。

## 建议的代理参与顺序（典型流程）

**注意：** 这是一般指南。BMAD 方法是迭代的；阶段/代理可能会被重新访问。

1. **分析师** - 头脑风暴并创建项目简报。
2. **PM（产品经理）** - 使用简报生成带有高级史诗和故事的 PRD。
3. **设计架构师为 PRD 创建 UX UI 规范（如果项目有 UI）** - 创建前端 UX/UI 规范。
4. **架构师** - 创建架构并确保我们能够技术上满足 PRD 要求 - 提供足够的规范，使开发代理能够一致地工作。
5. **设计架构师（如果项目有 UI）** - 创建前端架构并确保我们能够技术上满足 PRD 要求 - 提供足够的规范，使开发代理能够一致地工作。
6. **设计架构师（如果项目有 UI）** - 可选地创建提示以从 Lovable 或 Vercel 的 V0 等 AI 服务生成 UI。
7. **PO：** 验证文档是否一致，顺序是否合理，运行最终主清单。PO 还可以帮助中期开发重新规划或纠正方向，如果发生重大变更。
8. **PO 或 SM：** 一次生成一个故事（或多个，但不推荐） - 这通常在 IDE 中完成，在每个故事被开发者代理完成后。
9. **开发者代理：** 一次实现一个故事。您可以创建不同的专门开发者代理，或使用通用开发者代理。建议创建专门的开发者代理并在 `ide-bmad-orchestrator.cfg` 中配置它们。

## 处理重大变更

重大变更是雄心勃勃项目的固有部分。BMAD 方法通过其迭代性质和特定的代理角色来拥抱这一点：

- **设计为迭代：** 整个 BMAD 工作流建立在"ITERATIVE_REFINEMENT"之上。随着新信息的出现或需求的演变，预期会重新访问之前的步骤和代理。它"不是一个线性过程"。
- **拥抱和适应：** 核心理念包括"EMBRACE_THE_CHAOS"和"ADAPT & EXPERIMENT"。重大变更是完善愿景和方法的机会。
- **PO 在重新规划中的角色：** **产品负责人（PO）** 在管理重大变更的影响方面至关重要。他们可以"帮助中期开发重新规划或纠正方向，如果发生重大变更"。这涉及重新评估优先级，调整待办事项，确保与整体项目目标一致。
- **Vibe CEO 的战略监督：** 作为"Vibe CEO"，您的角色是保持"STRATEGIC_OVERSIGHT"。当重大变更出现时，您指导必要的转向，确保项目保持与您的单一愿景一致。
- **根据需要重新参与代理：** 如果变更显著改变了项目的范围或基础，不要犹豫重新参与早期阶段的代理（如分析师重新评估市场适应性，PM 修改 PRD，架构师评估技术影响）。

## IDE 与 UI 使用 - 一般建议

BMAD 方法可以通过不同的界面进行编排，通常使用 Web UI 进行更高级别的规划，使用 IDE 进行开发和详细的开发者故事生成。最一般的建议是从简报、PRD、架构、设计架构和潜在的 UI 提示生成所有文档。还使用 PO 运行完整的最终清单，确保所有文档与各种变更保持一致。例如，架构师是否发现了需要更新 PRD 中史诗或故事顺序的内容？PO 将在这里帮助您。完成后，将文档导出到 IDE。如果文档已被修改，您可以要求 Gemini 或 chatGPT 中的特定适当代理给您最终的未编辑完整文档。将这些保存到项目的 docs 文件夹中。

### 概念、规划阶段和技术设计

- **界面：** 通常最好通过 Web UI（利用带有捆绑资产和 `agent-prompt.txt` 的 **Web 代理编排器**）或专用项目管理工具进行管理，编排器代理可以指导流程。
- **涉及的代理：**
  - **分析师：** 头脑风暴、研究和初始项目简报创建。
  - **PM（产品经理）：** PRD 开发、史诗和高级故事定义。
  - **架构师/设计架构师（UI）：** 详细的技术设计和规范。
  - **PO：** 清单运行者，确保所有文档一致。
- **活动：** 定义愿景、初始需求收集、市场分析、高级规划。`web-bmad-orchestrator-agent.md` 及其配置可能支持这些活动。

### 文档管理和实施阶段

- **界面：** 主要在集成开发环境（IDE）中，利用专门的代理（独立的或通过由 `ide-bmad-orchestrator.cfg.md` 配置的 **IDE 代理编排器**）。
- **涉及的代理：**
  - "**PO 或 SM 或 BMad 代理：** 运行文档共享任务，将已创建的大型文件（PRD、架构等）分割成更小、更细粒度的文档，使 SM 和 Dev 代理更容易处理。
  - **SM（Scrum Master）：** 详细的故事生成、待办事项优化，通常在 IDE 或与之集成的工具中直接进行。
  - **开发者代理：** 在 IDE 中直接与代码库一起实现故事。
- **活动：** 详细架构、前端/后端设计、代码开发、测试，利用 IDE 任务（参见"利用 IDE 任务提高效率"），使用 `ide-bmad-orchestrator.cfg.md` 等配置。

了解关键文件有助于导航和自定义 BMAD 流程：

  - 代码库和相关开发文件。

## 利用 IDE 任务提高效率

### IDE 任务的目的

- **减少代理膨胀：** 避免将众多、很少使用的指令添加到主要 IDE 代理模式（Dev 代理、SM 代理）或甚至编排器的基础提示中。保持代理精简，对限制自定义代理复杂性/数量的 IDE 有益。
- **按需功能：** 通过提供相关任务文件（如来自 `bmad-agent/tasks/checklist-run-task.md`）的内容作为提示，或如果代理配置为查找它（如 IDE 编排器），则通过引用它，指示活动 IDE 代理（独立的或 IDE 编排器中体现的角色）执行任务。
- **多功能性：** 任何足够有能力的代理都可以被要求执行任务。任务可以处理特定功能，如运行清单、创建故事、分片文档、索引库等。它们是自包含的指令集。

### 任务功能示例

**概念：** 将任务视为专门的、可调用的迷你代理或按需指令集，主 IDE 代理或编排器（当体现角色时）可以调用，保持主要代理定义的精简。它们对于不经常执行的操作特别有用。`docs/instruction.md` 文件提供了有关任务设置和使用的更多详细信息。

以下是 `bmad-agent/tasks/` 中任务提供的一些功能示例：

- **`create-prd.md`：** 指导生成产品需求文档。
- **`create-next-story-task.md`：** 帮助定义和创建下一个用户故事进行开发。
- **`create-architecture.md`：** 协助概述项目的技术架构。
- **`create-frontend-architecture.md`：** 专门专注于设计前端架构。
- **`create-uxui-spec.md`：** 促进创建 UX/UI 规范文档。
- **`create-ai-frontend-prompt.md`：** 帮助起草用于 AI 服务生成 UI/前端元素的提示。
- **`doc-sharding-task.md`：** 提供将大型文档分解为更小、可管理部分的过程。
- **`library-indexing-task.md`：** 协助创建代码库的索引或概述。
- **`checklist-run-task.md`：** 执行预定义的清单（可能使用 `checklist-mappings.yml`）。
- **`correct-course.md`：** 提供项目需要调整方向时的指导或步骤。
- **`create-deep-research-prompt.md`：** 帮助制定用于对主题进行深入研究的提示。

这些任务允许代理通过遵循每个任务文件中的详细指令来执行复杂的、多步骤操作，通常根据需要利用模板和清单。
